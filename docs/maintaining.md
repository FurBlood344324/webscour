# Maintaining

For one maintainer. Everything here is a procedure with a command in it, because the version
lives in four places that must agree: `webscour/__init__.py` (the only source), `CHANGELOG.md`,
the git tag, and the PyPI release.

## Cutting a version

```bash
git switch main && git pull
./scripts/release.sh 0.2.0          # add --dry-run first to see the steps without writing
```

It refuses a dirty tree, refuses a version that is not higher than `webscour.__version__`, runs
`./scripts/check.sh` and stops if it fails, stamps the version into `webscour/__init__.py` and
the two manifests, moves the hand-written `## Unreleased` notes into the new section, prepends a
section generated by `git cliff` from `cliff.toml`, commits `chore(release): 0.2.0`, and creates
the annotated tag `v0.2.0`. It never pushes and never publishes; it prints the commands instead.
`git cliff` is optional: without it the section says so in the file, which is visible and fixable.

## What is manual, on purpose

1. **Push the branch and the tag.** `git push origin HEAD && git push origin v0.2.0`. Pushing
   the tag is the publish: `release.yml` triggers on `v*`, re-runs `check.sh`, verifies the tag
   equals `__version__` through `scripts/check-tag.sh`, and hands the wheel it just tested to
   PyPI. `release.sh` also prints a `twine upload` line; that is the fallback for a day when
   Actions is down, it needs a token, and it is not the normal path.
2. **Confirm the trusted publisher.** The publish job runs in the `pypi` environment and
   authenticates through OIDC, so there is no token to rotate. If that environment has a required
   reviewer, approving the run is the second factor and is not automatable.
3. **Read the GitHub Release.** Its body is `scripts/changelog-section.sh <version>`, so the
   notes and the changelog are the same text. An empty body means the changelog had no section.

## Verifying the published wheel

```bash
python3 -m venv /tmp/wswheel && /tmp/wswheel/bin/pip install --no-cache-dir webscour==0.2.0
/tmp/wswheel/bin/wsc --version        # the version you just cut
/tmp/wswheel/bin/wsc --self-test      # offline checks, no network needed
```

`check.sh` already fails when the wheel is missing a module, carries `tests/`, or lacks the four
`searx` data files. If the installed version is not the tag, cut a new patch version: PyPI does
not accept a second upload of the same file name.

## The benchmark baseline

`tests/baselines/<version>.json` is the number future versions must beat, and the benchmark
compares against the newest file there (lexical order, so name it for the version). Regenerate it
only when an extraction change is meant to move the numbers:

```bash
python3 -m venv /tmp/tfvenv && /tmp/tfvenv/bin/pip install trafilatura   # the reference column
python3 tests/bench_extract.py --live --save-baseline tests/baselines/0.2.0.json
```

`--live` re-fetches the six pages, so fixture and baseline move together and the diff is honest.
Commit both and state the per-page diff in the pull request. Never edit a baseline by hand and
never delete an old one: the sequence is the evidence that extraction is not drifting.
`BENCH=1 ./scripts/check.sh` is the gate that includes this, deliberately not the default because
it leaves the machine.

## Rotating the SearXNG pin

`searx/install.sh` pins a commit, not a tag, because a tag can move and a hash cannot. To move
it: pick the new upstream commit, edit that one line, run `wsc setup --force`, then `wsc doctor`
and `wsc probe --quality --write`, and record the new engine table in `searx/README.md` with its
date. A pin move that changes behaviour gets a decision record; a patch bump inside the same
release does not.

## The quarterly check

Two facts rot with time and code review sees neither. Once a quarter, on a normal connection:

1. **The measured engine table.** `wsc probe --quality --write`, then compare with `README.md`
   and `searx/README.md`. Engines below the coverage 10 percent / precision 60 percent bar are
   dropped; recovered ones named. Date the table by when it was measured.
2. **Source reachability.** `gh workflow run upstream-check.yml`. It writes
   `.agent-out/upstream-check.txt` and lists which structured APIs and scraped pages still
   answer. A red line is the only signal that a third party's HTML moved, and it blocks nothing.
3. **Pins.** `./scripts/deps-check.sh` for the action refs and lightpanda's flags. The weekly
   `deps` workflow opens an issue when a fact changes; read the DRIFT line before closing it.

## If I am unavailable

State lives in four places and none of them is in a person's head: the repository (code,
decisions in `docs/decisions/`, history), `CHANGELOG.md` (what each version changed, in prose),
the PyPI project (whose trusted publisher is bound to this repository and the `pypi`
environment), and the per-machine SearXNG install, rebuildable with `wsc setup --force`.

A successor needs commit access, the PyPI owner role, and `./scripts/check.sh` passing locally.
Nothing else is required to cut a release, and no secret sits in the repository: the release path
is OIDC and the SearXNG secret is generated at install time.
